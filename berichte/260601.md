## Zielsetzung

- Grundlagen der x86-64 Assemblersprache verstehen (Register, Opcodes, Sprungbefehle)
- Ein kompiliertes Binary mit dem GNU Debugger (`gdb`) analysieren
- Maschinenbefehle zur Laufzeit patchen (`je` → `nop`, `add` → `sub`)
- Patches direkt ins Binary schreiben (`hexedit`)
- Den Unterschied zwischen `je` und `jne` auf Opcode-Ebene verstehen

## Übung – GNU Debugger (pwn / nop-Patch)

### Szenario

Das Passwort ist unbekannt. Ziel ist es, die Passwortprüfung im Speicher zu deaktivieren, indem der `je`-Sprungbefehl mit `nop`-Befehlen überschrieben wird.

### Analyse mit gdb

```bash
gdb ./pwcheck
```

```
(gdb) disas main
```

Relevanter Ausschnitt:

```
0x00000000000011a2 <+66>:    cmp    $0x0,%eax
0x00000000000011a5 <+69>:    je     0x123d <main()+221>
```

> `check_password` gibt 0 zurück wenn das Passwort falsch ist. Der `je`-Befehl springt dann zur „Wrong"-Meldung. Wird der Sprung entfernt, läuft das Programm durch.

### Basisadresse ermitteln

```
(gdb) break main
(gdb) run
(gdb) info address main
Symbol "main()" is a function at address 0x555555555160.
```

### Opcode-Größe prüfen

```
(gdb) x/8xb 0x5555555551a5
0x5555555551a5: 0x0f  0x84  0x92  0x00  0x00  0x00  0x48  0x8d
```

> `je` mit 32-Bit-Offset = 6 Bytes (`0f 84 xx xx xx xx`). Alle 6 Bytes müssen mit `nop` (0x90) überschrieben werden.

### Patch setzen

```
(gdb) set {unsigned char}0x5555555551a5 = 0x90
(gdb) set {unsigned char}0x5555555551a6 = 0x90
(gdb) set {unsigned char}0x5555555551a7 = 0x90
(gdb) set {unsigned char}0x5555555551a8 = 0x90
(gdb) set {unsigned char}0x5555555551a9 = 0x90
(gdb) set {unsigned char}0x5555555551aa = 0x90
(gdb) continue
```

### Ergebnis

```
Enter password: test
Correct
Password was: G7pL9xQ2mR4tZcH
```

> Durch das Überschreiben des `je`-Befehls mit 6x `nop` wird die Passwortprüfung umgangen. Das Programm gibt das korrekte Passwort aus: **`G7pL9xQ2mR4tZcH`**

## Übung – pwn add to sub

### Szenario

Nach der Passwortprüfung führt das Programm eine Addition durch. Ziel ist es, den `add`-Opcode durch `sub` zu ersetzen.

### Relevante Instruktion

```
0x0000555555555224 <+196>:   add    -0xc(%rbp),%eax
```

### Opcode prüfen

```
(gdb) x/4xb 0x555555555224
0x555555555224: 0x03  0x45  0xf4  0x89
```

| Opcode | Befehl |
|--------|--------|
| `0x03` | `add` |
| `0x2b` | `sub` |

### Patch setzen

```
(gdb) set {unsigned char}0x555555555224 = 0x2b
(gdb) continue
```

### Ergebnis

```
Enter password: test
Correct
Password was: G7pL9xQ2mR4tZcH
a=5
b=3
Result=2
```

> Statt `5+3=8` rechnet das Programm nun `5-3=2`. Der `add`-Opcode `0x03` wurde durch `sub`-Opcode `0x2b` ersetzt.

## Übung – Binary File Patching I

### Szenario

Die Patches aus dem gdb gelten nur zur Laufzeit. Mit `hexedit` werden die Bytes direkt ins Binary geschrieben und sind damit dauerhaft.

### je → nop (6 Bytes)

```bash
hexedit pwcheck
```

- `Ctrl+G` → Offset `11a5` → Enter
- 6x `90` eingeben (`909090909090`)
- `Ctrl+X` → `Y` (speichern)

### Ergebnis

```bash
./pwcheck
Enter password: test
Correct
Password was: G7pL9xQ2mR4tZcH
a=1
b=5
Result=6
```

> Die Passwortprüfung ist dauerhaft deaktiviert. Addition ist noch aktiv (`1+5=6`).

## Übung – Binary File Patching II & jne

### Binary File Patching II – add → sub

```bash
hexedit pwcheck
```

- `Ctrl+G` → Offset `1224` → Enter
- `2b` eingeben
- `Ctrl+X` → `Y`

```bash
./pwcheck
Enter password: test
Correct
Password was: G7pL9xQ2mR4tZcH
a=1
b=5
Result=-4
```

> `1-5=-4` bestätigt den erfolgreichen `sub`-Patch im Binary.

### jne-Patch

Statt `nop` wird der `je`-Befehl durch `jne` ersetzt. Das Binary wurde zuerst neu heruntergeladen:

```bash
wget -O pwcheck https://www.franzmatejka.at/htl/doc/ITSI_2_linux/opcode_patching/bin/kali/pwcheck
chmod +x pwcheck
```

| Opcode | Befehl |
|--------|--------|
| `0f 84` | `je` (Jump if Equal, ZF=1) |
| `0f 85` | `jne` (Jump if Not Equal, ZF=0) |

```bash
hexedit pwcheck
```

- `Ctrl+G` → Offset `11a5` → Enter
- Cursor ein Schritt nach rechts (auf `84`)
- `85` eingeben
- `Ctrl+X` → `Y`

```bash
./pwcheck
Enter password: test
Correct
Password was: G7pL9xQ2mR4tZcH
a=1
b=5
Result=6
```

> Bei falschem Passwort ist `ZF=0` → `jne` springt **nicht** → Programm läuft durch zur „Correct"-Meldung. Gleiches Ergebnis wie der nop-Patch, aber mit nur 1 geändertem Byte.
